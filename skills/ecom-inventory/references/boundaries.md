# Boundary Conditions: ecom-inventory

When this skill should NOT be used. Generated from chapter boundary sections.

### From a5-inventory.md

- **销售历史不足一年。** 季节性分解和安全库存的计算都要求至少覆盖一个完整年周期。只有几个月数据时，模型会把一次促销的尖峰当成季节性规律，据此备货会在下一个平季严重压货。新品期该用保守的固定天数备货，等数据够了再上模型。
- **供应链交期本身不稳定。** 再订货点的计算假设 lead time 是个已知数。如果你的工厂交期在 30 到 75 天之间随行情浮动，算出来的补货点精度是假的。这种情况下该做的是把交期波动本身当成主要风险来管（多留安全库存、备选供应商），而不是优化预测精度。
- **断货过或者被限仓过。** 断货期间销量为 0 不代表需求为 0，限仓期间的销量也不是真实需求。这些数据直接喂给预测模型，它会学到"这几周需求本来就低"。本章的断货处理逻辑能补一部分，但被平台限仓、跟卖抢走 Buy Box 这类污染需要你自己标出来。
- **品类的需求由外部事件驱动。** 节日礼品、考试季用品、跟着某个热点走的品——这类需求不是时间序列的延续，是事件的函数。预测模型在这些品类上会稳定地滞后一个周期。该做的是把日历事件作为外部变量显式加进去，或者干脆按事件手工排产。
