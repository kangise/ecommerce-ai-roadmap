# v1.3.0 Amazon Operator Pilot — Release Candidate 合同

日期：2026-08-26
状态：L0–L13 实现已验证；L5 真实 Ads 准入保持外部 blocked 并已在 RC 签收，L6 已按硬门保持未安装且零写入

## 目标

交付一个以真实 Amazon 数据和受控人工审批为边界的 Operator Pilot，形成可恢复、可审计的日常运营闭环：

`Reports → Evidence → 领域 Agents → Manager/Reviewer → Daily Brief → Proposal/审批`

试点必须使用真实已授权 Amazon 账户和实际报告；所有可改变外部状态的动作必须以 Proposal 表达，并在授权审批后才执行。

## 非目标

- 不以 mock 数据、伪造指标、假 API 延迟或静态仪表盘代替真实链路。
- 不绕过身份验证、授权、租户归属或审批。
- 不在未经批准的情况下自动修改 Amazon Ads、商品、库存或账户设置。
- 不承诺所有 Amazon Ads 能力；该部分以外部权限和 API 可用性为前提。
- 不将试点扩展为通用多市场、全自动投放或无人值守生产系统。

## 每轮强制纵向模式

每个 Loop 均须按以下顺序完成，缺一不可：

1. 确认或定义数据模型（含 tenant ownership）。
2. 实现真实 service/API layer。
3. 连接 UI 至真实数据，不添加运行时 mock。
4. 添加输入、状态和业务验证。
5. 添加 authentication 与 authorization。
6. 覆盖 loading、empty、success、failure 状态；可见按钮必须有真实动作、路由、模态框，或明确禁用原因。
7. 添加测试。
8. 更新文档、限制与操作说明。
9. 执行安装与 smoke 验证，确认刷新后数据和状态仍被持久化。

每轮完成前，进度账本必须附上证据位置、单一动作提交（commit）和说明；不得将多个不相干动作混入同一提交。

## 验证器与状态门

每轮至少通过以下验证器，实际命令以仓库可用脚本为准：

- 数据模型/迁移检查：可创建、读取、刷新后仍存在，并具备租户归属。
- 服务/API 检查：真实授权路径返回可审计结果；错误不被静默吞掉。
- UI 检查：真实数据和四类状态均可观察，按钮符合 Button rule。
- 权限检查：未认证、跨租户、无审批权等请求被拒绝。
- 测试检查：本轮新增行为有自动化测试。
- 安装 smoke：从干净或明确的环境按文档安装并运行最小真实链路。
- 文档检查：证据、限制、恢复点和操作步骤同步更新。

只有验证器全部通过，才可将该 Loop 标记为 `done` 并开始下一轮。

## 阻塞与升级规则

- 同一 Loop 对同一根因连续失败两次，必须标记为 `blocked`，停止继续试错，并记录失败证据、根因假设、已尝试修复和所需外部输入。
- `blocked` 不能用 mock、硬编码、权限绕过或空实现伪装为完成；只可在根因解除、验证器重新通过后恢复为 `in_progress`。
- 外部依赖缺失（凭证、角色、账户、审批、API 配额或 Amazon 服务可用性）是有效阻塞，应明确报告。

## Amazon Ads 外部阻塞规则

L5 是 L6 的硬门。只有当以下条件均有真实证据时，L5 才能通过：广告账户已正确关联租户、所需 Amazon Ads API 权限和角色已获批、目标端点/区域/广告类型可用、凭证与刷新流程可运行、最小读操作在真实账户成功且审计留痕。

任一条件未满足时：L5 标记 `blocked`，L6 保持 `pending`；不得创建模拟 Ads adapter、伪造广告数据或发布会影响 Ads 的 Proposal。可继续推进不依赖 Ads 的 Loop，但必须在 Daily Brief 与 RC 限制中持续显示该外部阻塞。

## 恢复规则

每轮开始前记录可恢复基线（上一有效 commit、迁移状态、配置版本、证据位置）。失败后：

1. 保留失败日志、请求标识与证据；不删除审计记录。
2. 回到最近验证通过的单一动作提交或等价可重复状态；不通过覆盖共享数据来“修复”。
3. 重新执行本轮验证器和安装 smoke，确认恢复后的真实链路。
4. 在进度账本记录恢复动作、原因和结果。

任何涉及外部写入的恢复都必须遵守原有审批和最小权限边界；不得通过逆向外部写入来掩盖错误。

## v1.3.0 退出条件

版本仅在以下条件同时满足时退出：

- L0–L13 均为 `done`，或明确批准的外部阻塞按本合同保留并在 RC 中签收。
- Reports 到 Evidence 到领域 Agents 到 Manager/Reviewer 到 Daily Brief 到 Proposal/审批的真实端到端链路可演示、可刷新、可审计。
- 所有持久化数据有租户归属；权限、验证、四态 UI、测试、文档和安装 smoke 均已完成。
- 每轮有可定位 evidence、单一动作 commit 与 notes；L12 恢复演练通过。
- 无未说明的 mock、硬编码生产指标、静默错误、无作用可见按钮或未授权外部写入。
